## 1. Що це за додаток

Соціальна платформа для тенісистів-аматорів. **Ринок запуску — Київ/Україна, продукт від старту двомовний (EN + UK) і не привʼязаний до однієї країни** (див. §11).

- знайти партнера по грі поблизу свого рівня;
- знайти корт і забронювати час гри;
- вести рейтинг (бали ліги + рівень NTRP) на основі реально зіграних матчів;
- турніри: анонси, реєстрація, сітка, результати;
- чат між гравцями та в турнірах.

**Юридичний момент:** ідею (спільнота для пошуку партнерів) відтворювати нормально, а назву,
логотип, іконки й тексти PairUp — ні. Усе брендування робимо своє (див. §12).

## 2. Технічні рішення (зафіксовані)

| Шар | Рішення | Чому саме так |
|---|---|---|
| Мобільний застосунок | **React Native + Expo** (managed workflow) | один код на iPhone і Android; збірка iOS без Mac через EAS Build |
| Мова | **TypeScript** | агент і редактор ловлять помилки до запуску — критично для новачка |
| Навігація | **Expo Router** (file-based) | структура екранів = структура папок, легко читати |
| Стан + дані | **TanStack Query** + Zustand (мінімально) | кеш серверних даних «з коробки», без ручного Redux |
| Бекенд | **Supabase** (Postgres + Auth + Storage + Realtime + Edge Functions) | одна платформа замість чотирьох сервісів, є SDK для React Native |
| Серверна логіка | **Supabase Edge Functions** (Deno/TypeScript) | перерахунок рейтингу, генерація сіток, розсилка пушів |
| Карта | `react-native-maps` (Google Maps) | екран «Корти» |
| Пуш-повідомлення | `expo-notifications` + Expo Push Service | безкоштовно, працює на обох платформах |
| Код | **GitHub** (приватний репозиторій) | історія змін, бекап, CI |
| CI/CD | **GitHub Actions** + **EAS Build/Submit** | автоперевірка коду в PR, збірки для сторів |
| Vercel | **не на старті** | потрібен пізніше: лендінг, deep links, адмін-панель (Next.js) |
| Аналітика/краші | PostHog (free) + Sentry (free) | бачити, де падає і де користувач застряг |

### Чому Supabase, а не Firebase

Дані додатку — реляційні за природою: гравець → матч → сети → бали рейтингу → турнірна сітка.
У Postgres такі перерахунки й вибірки (наприклад «топ-50 по місту за останні 12 місяців»)
робляться одним запитом. У Firebase (документна БД) це перетворюється в ручну денормалізацію.
Плюс Row Level Security дає захист даних на рівні бази, а не на рівні коду додатку.

### Чому Vercel не потрібен зараз

Supabase уже вміє все, що потрібно бекенду мобільного застосунку. Vercel беремо в Фазі 8, коли
знадобиться:
- публічний лендінг на власному домені + сторінки Privacy Policy / Terms (їх **вимагають** App Store і Google Play);
- файли `apple-app-site-association` і `assetlinks.json` для deep links (посилання «Приєднатися до турніру» відкриває додаток);
- веб-адмінка для модерації та підтвердження NTRP.

## 3. Дизайн-система (витягнута з фото-референсу)

Напрямок: **темна «глиняна» тема**, преміальна, з фото як акцентом. Це замінює світлий Apple-стиль,
який обговорювався раніше в чаті.

### Кольори (токени)

```
bg.surface     #221B16   // карточки, списки

// Глина (основний акцент — Roland Garros)

clay.600       #A84A28   // натиснутий стан

// Тенісний м'яч (акцент дії)

// Текст
text.primary   #F5F0EA

```

### Типографіка

- Заголовки: **Inter Tight / SF Pro Display**, 700, tight tracking.
- Логотип: wordmark `GOLDEN SET` у векторі (SVG) + м’яч як акцент. Латиниця — одна версія на обидві мови. Іконка застосунку: монограма `GS` на глиняному тлі з золотою обвідкою.
- Цифри рейтингу: tabular figures (`fontVariant: ['tabular-nums']`), щоб колонка не «стрибала».

### Компоненти з референсу

1. **Hero-хедер** — фото корту з градієнтом затемнення донизу, логотип, дзвіночок з бейджем, аватар.
2. **Segmented control** — пігулка з 4 іконок+підписів (Рейтинг / Турніри / Календар / Профіль), активна — глиняна.
3. **Картка списку рейтингу** — місце, аватар у кільці, нік + місто, бали (gold) + дельта (green), шеврон.
   Лідер виділений глиняним фоном і рамкою.
4. **Значок рівня** — золота плашка `NTRP 4.5` / `UTR 9.5`. Спочатку був зеленим тенісним м'ячем,
   але м'яч у застосунку означає дію (кнопка «створити»), тож рейтинг у тій самій формі читався як
   кнопка. М'яч лишився тільки там, де щось натискають.
5. **Банер «Наступний турнір»** — глиняна картка з м'ячиком і круглою кнопкою-стрілкою.
6. **Нижнє меню** — 5 позицій, центральна — плаваюча кнопка-м'ячик (створити гру / записати матч).

Усе це збираємо як `components/ui/*` з токенів, **до** написання екранів. Правило: у файлах екранів
немає жодного хардкоду кольору чи відступу.

**RLS з першого дня.** Базові правила: профіль читають усі авторизовані, редагує тільки власник;

**виключно** Edge Function через service role — з клієнта бали не змінюються ніколи.

## 5. Логіка рейтингу (те, що відкладали в чаті)

Дві незалежні шкали — не змішувати:

**1. Бали ліги (те, що на фото: 2487, +24).** Elo-подібна система:

```
expected_a = 1 / (1 + 10^((points_b - points_a) / 400))
delta_a    = round(K * margin * (result_a - expected_a))
```

- `K` = 40 для перших 10 матчів гравця, далі 24, і 16 при points > 2200 (щоб топ не «стрибав»);
- `margin` — коефіцієнт 0.8–1.2 залежно від різниці в геймах (перемога 6:0 6:0 важить більше, ніж 7:6 7:6);
- старт — 1200 балів, публічний рейтинг лише після 5 підтверджених матчів (до того — бейдж «Новий»);
- давність: бали не згорають, але в рейтингових таблицях за замовчуванням фільтр «активні за 12 міс».
- **Антифрод:** обидві сторони підтверджують результат; матч між тими самими гравцями частіше
  ніж 1 раз на 24 год дає знижений `K`; підозрілі серії — на модерацію.

**2. NTRP (1.0–7.0, крок 0.5).** Рівень гри, не результат:

- на старті гравець вказує сам (`ntrp_source = self`) через короткий опитувальник-калібратор;
- значок з фото показує саме NTRP;
- уточнення: авто-підказка з балів (`points → діапазон NTRP`) + верифікація тренером/організатором
  через `ntrp_reviews` → `ntrp_source = verified`, і тоді значок отримує галочку.

**Важливо для міжнародної версії.** NTRP — американська шкала (USTA), за межами США її майже не
використовують. Світовий стандарт — **UTR** (1–16.5, Європа та юніорський теніс), у падел-світі — DUPR.
Тому в базі тримаємо `level_scale(ntrp|utr)` + `level_value`, а значок з фото показує ту шкалу, яка
вибрана в налаштуваннях. Це 20 рядків коду зараз — і врятований рефакторинг усього рейтингу потім,
коли додаток вийде за межі України.

Реалізація: Edge Function `recalc-rating` викликається тригером на `match_confirms`, коли підтверджень
стало достатньо. Уся математика в одному місці, покрита юніт-тестами (це той код, який має тести
обов'язково — решту тестуємо руками).

## 6. Екрани (обсяг MVP)

**Онбординг:** splash з фото-референсу → вхід (Apple / Google / email) → нік, місто, фото → калібратор NTRP.

**Головна (Рейтинг)** — екран з фото. Segmented: Рейтинг / Турніри / Календар / Профіль.
Фільтр регіону, топ-список, банер наступного турніру.

**Пошук** — гравці поблизу (фільтри: місто, NTRP ±0.5, стать, вік) + відкриті заявки на гру.

**Кнопка-м'ячик (FAB)** — модалка з двома діями: «Створити гру» і «Записати результат матчу».

**Корти** — карта + список, картка корту (покриття, освітлення, ціна, телефон, фото).

**Турніри** — список, картка турніру, реєстрація, сітка, результати.

**Календар** — мої ігри й турніри, нагадування.

**Повідомлення** — список тредів, чат (Realtime), непрочитані.

**Профіль** — хедер з NTRP-значком і балами, графік динаміки балів, історія матчів, статистика
(W/L, найкраща перемога), налаштування, вихід, видалення акаунта (**вимога Apple**).

## 8. Робочий процес

**Гілки:** `main` (завжди робочий) → `feat/*` для кожної задачі → PR → merge. Ніколи не пушити прямо в `main`.

**Кожна фаза = один PR** (або кілька, якщо велика). У PR: що змінилось + скріншот екрана.

**Секрети:** `.env` у `.gitignore` **завжди**. У репо тільки `.env.example`.
- `EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY` — можна на клієнті (їх захищає RLS);
- `SUPABASE_SERVICE_ROLE_KEY` — **лише** в секретах Edge Functions і GitHub Actions, ніколи в застосунку.

**Міграції БД:** тільки через Supabase CLI (`supabase migration new ...`), файли в `supabase/migrations/`
під git. Не редагувати таблиці руками в дашборді — інакше локальна й продакшн-база розʼїдуться.

**Тестування:**
- iPhone — Expo Go (без Mac), потім TestFlight на Фазі 8;
- Android — Expo Go на реальному телефоні або емулятор Android Studio;
- юніт-тести (Jest) — обовʼязково для формул рейтингу і генерації сітки, решта — ручна перевірка.

**Структура проєкту:**
```
Court/
  app/                 # екрани (Expo Router)
  components/ui/       # дизайн-система
  features/            # rating/ tournaments/ chat/ courts/ ... (логіка + хуки)
  lib/                 # supabase client, формати, дати
  theme/               # tokens.ts, typography.ts
  supabase/
    migrations/
    functions/         # recalc-rating, build-bracket, send-push
  assets/              # фото-референс, іконки, шрифти
  docs/                # PLAN.md, DESIGN.md, DECISIONS.md
  CLAUDE.md
```

## 11. Двомовність від першого дня (i18n)

Рішення: **англійська — базова мова коду й контенту, українська — перша локалізація.** Не «спочатку
українською, потім перекладемо» — переклад заднім числом означає переверстку половини екранів.

### Технічно

| Що | Як |
|---|---|
| Бібліотека | `i18next` + `react-i18next` + `expo-localization` |
| Файли перекладів | `locales/en.json`, `locales/uk.json` — плоскі ключі: `rating.title`, `match.confirm.cta` |
| Мова за замовчуванням | системна мова телефону, з можливістю перемкнути в Профілі; fallback → `en` |
| Плюралізація | тільки через i18next (`{{count}}` + `_one/_few/_many`) — в українській 3 форми, в англійській 2 |
| Дати/числа | `Intl.DateTimeFormat` / `Intl.NumberFormat` з поточною локаллю, ніякого ручного `dd.MM.yyyy` |
| Валюта | поле `currency` в турнірах уже є — форматувати через `Intl`, не хардкодити «грн» |

### Правило коду (перевіряється в PR)

У JSX **немає жодного рядка тексту** — тільки `t('key')`. ESLint-правило проти літералів у JSX
ставимо у Фазі 0, щоб порушення ловились одразу, а не через 3 місяці.

### Контент у базі

Назви й описи, які вводять користувачі (турніри, корти), **не перекладаємо** — зберігаємо як є
плюс поле `lang`. А от системні довідники перекладаємо:

```
surfaces / tournament_formats / notification_kinds  -- ключ + en/uk через таблицю *_i18n
                                                    -- або enum у коді + переклад у locales
```
Для MVP простіше: enum у коді + ключі в `locales`. Таблиці-довідники — коли зʼявиться адмінка.

### Що ще ламається без підготовки

- **Довжина рядків.** Українські підписи в середньому на 20–30% довші за англійські. Нижнє меню з
  5 підписів («Повідомлення» vs «Chat») — перше місце, де це вилізе. Тестуємо обидві мови на
  кожному екрані Фази 2, а не в кінці.
- **Логотип.** Якщо в назві є кириличний елемент — він не працює на англомовному ринку. Тому
  назва латиницею, одна для обох мов (див. §12).
- **Скріншоти в сторах.** Готуються окремо для кожної локалі, це подвоює роботу у Фазі 8 — врахувати в оцінці.

## 12. Назва, брендинг і ШІ-графіка

### Чи можна використовувати згенеровану ШІ картинку — так, можна

Заборони немає, і сторам це теж все одно: ні App Store, ні Google Play не забороняють ШІ-асети.
Умови ChatGPT/DALL-E передають права на вихідне зображення користувачу, включно з комерційним
використанням. Тобто **взяти те фото і використати його в додатку — легально**.

Реальна відмінність в іншому — у тому, що ти **отримуєш** разом із таким зображенням:

| | Намальовано людиною / куплено ліцензію | Згенеровано ШІ |
|---|---|---|
| Право використати | так | **так** |
| Авторське право на саме зображення | є | у більшості юрисдикцій (США, ЄС) **немає** — немає людського авторства |
| В Україні | авторське право | **sui generis** право на «неоригінальний обʼєкт, згенерований компʼютерною програмою» (ст. 33 ЗУ «Про авторське право і суміжні права» 2022) — 25 років, окремий режим |
| Заборонити конкуренту скопіювати той самий файл | сильна позиція | слабка (спираєшся тільки на торгову марку) |
| Торгова марка на логотип | реєструється | **теж реєструється** — ТМ не вимагає авторства |

Практичний висновок, а не юридична паніка:

1. **Hero-фото м'яча на корті — використовуй спокійно.** Це декоративне тло, і навіть якщо хтось
   візьме таке саме — нічого не станеться. Єдина перевірка: щоб на зображенні випадково не було
   логотипів реальних турнірів/брендів (ШІ любить домальовувати щось схоже на Wilson чи RG) і
   розпізнаваних облич.
2. **Логотип — інша історія, і тут проблема технічна, а не юридична.** JPEG 860×1900 не є
   набором брендових асетів. Потрібно: вектор (SVG), іконка застосунку в ~15 розмірах, варіант на
   прозорому фоні, монохромний варіант, splash під різні співвідношення сторін. Рельєфний
   «трав'яний» шрифт з фото до того ж не масштабується на іконку 40×40 і не читається. Тому логотип
   однаково доведеться перемалювати у векторі — незалежно від того, хто його згенерував.
3. **Що дійсно варто зробити з юридичного боку** — не «замінити ШІ-картинку», а зареєструвати
   **торгову марку** на фінальну назву й логотип (Україна: ~$150–300 через патентного повіреного;
   ЄС/США — дорожче). ТМ захищає бренд від конкурентів, і для неї походження картинки не має значення.

**Тобто моя попередня формулювання була неточною:** проблема не в тому, що «ШІ-графіку не можна»
— можна. Проблема в тому, що raster-логотип не годиться як асет і що бренд захищається торговою
маркою, а не авторським правом.

## 14. Версія Expo SDK і як ми тестуємо на iPhone

**Рішення (18.08.2026): проєкт закріплено на Expo SDK 54.**

### Чому не найновіша версія

Expo Go в App Store **застряг на SDK 54** — Expo чекає на схвалення Apple новіших версій, і термін
невідомий. Проєкт спочатку створився на SDK 57 (`create-expo-app` за замовчуванням ставить
найновішу), і телефон одразу відмовився його відкривати: `Project is incompatible with this version
of Expo Go`.

Це виправляє неточність у §7: обіцянка «iOS тестуємо безкоштовно через Expo Go» справджується
**лише** для SDK, який є в App Store.

### Що доступно на якому SDK

| Спосіб | SDK 54 | SDK 57 | Ціна |
|---|---|---|---|
| Expo Go з App Store (iPhone) | ✅ | ❌ | безкоштовно |
| Expo Go на Android через Expo CLI | ✅ | ✅ | безкоштовно |
| iOS-симулятор | ✅ | ✅ | потрібен Mac |
| `eas go` (власна збірка Expo Go в TestFlight) | ✅ | ✅ | **Apple Developer $99/рік** |
| Development build | ✅ | ✅ | **Apple Developer $99/рік** для iOS |

### Наслідки

- Розробка ведеться на SDK 54 доти, доки не з'явиться платний Apple-акаунт (Фаза 8).
- **SDK не піднімати, не перевіривши цю таблицю заново.** Оновлення до 57 сьогодні = втрата
  можливості дивитись додаток на iPhone.
- Коли в Фазі 8 з'явиться Apple Developer і development build — прив'язка до Expo Go зникає, і
  тоді підняти SDK можна буде вільно.
- Технічна різниця для нас мінімальна: React Native 0.81 замість 0.86, React 19.1 замість 19.2.
  Жодна функція з нашого коду цього не потребує.

## 15. Авторизація: що вирішено у Фазі 3

**Зараз працює тільки пошта + пароль.** Причина не технічна, а грошова: Apple вимагає
Sign in with Apple лише тоді, коли в застосунку є **інші** соціальні входи. Тобто додати Google
сьогодні = зобовʼязати себе додати Apple = купити Apple Developer ($99/рік) раніше, ніж потрібно.
Обидва провайдери додаємо у Фазі 8, коли акаунт зʼявиться в будь-якому разі.

### Правило, яке тримає база, а не код

`points`, `matches_played` і `level_source` — серверні колонки. Тригер `protect_server_owned_columns`
**мовчки повертає** їх старі значення при будь-якому оновленні не від `service_role`. Не помилка, а
саме відкат: клієнт може надіслати назад увесь обʼєкт профілю, і це спрацює — просто рейтинг не
зрушиться. Перевірено реальним PATCH-запитом з токеном користувача: `points` лишились 1200.

### Дві знахідки радника безпеки

1. `citext` виявився непотрібним — обмеження `username_shape` і так дозволяє лише нижній регістр,
   тож звичайний `text` дає ту саму нечутливість до регістру без розширення в схемі `public`.
2. Тригерні функції були доступні як REST-ендпойнти (`/rest/v1/rpc/handle_new_user`). Забрати
   `EXECUTE` в `anon` і `authenticated` **не допомагає** — право лежить у ролі `PUBLIC`, звідки
   обидві його успадковують. Тригери від цього не страждають: вони перевіряють право `TRIGGER` на
   таблиці, а не `EXECUTE` на функції.

### Пастка веб-збірки

Expo пререндерить веб-сторінки в Node, де немає `window`. `AsyncStorage` на вебі — обгортка над
`window.localStorage`, тому передача його в `supabase-js` як сховища сесії валила рендер ще до
монтування застосунку (`ReferenceError: window is not defined`). На нативі проблеми не було взагалі.
Тому адаптер передається **тільки на нативі**, а на вебі `supabase-js` обирає сховище сам і спершу
перевіряє наявність браузера.
